# framework-site — notes for agents

The public site (framework.co.ke), its Netlify functions, and the two gated
dashboards. `AGENTS.md` holds the catalog and WhatsApp-CTA rules — read it
before touching either; they are not repeated here.

## /builder

The 3D shelf designer at `/builder`. `docs/builder.md` is the full account of
how it works and why. The two things that waste an hour if missed:

- **Bump the version after any change** under `js/`, `css/` or `assets/`:
  `node scripts/bump-builder-version.mjs`. Everything loads on one `?v=N`, so a
  half-stale cache silently pairs new code with an old catalogue.
- **Cache-bust the HTML too when testing** (`builder.html?cb=<n>`) — the page
  itself carries no version.

```bash
npm run dev     # http://127.0.0.1:8770/builder — rewrites + the design function
npm test        # WhatsApp links, the track emitter, and the builder suite
```

## Where the geometry comes from

`assets/shelving/builder-contract.json` is **generated by the sibling
`framework-renderer` repo and checked in here**. It carries the modules,
sockets, prices, finishes, vocabulary and the pipeline's own golden validation
configs (which are this repo's test fixtures — do not copy them in by hand).

- `scripts/build-builder-assets.mjs` reads the vendored contract plus the
  pipeline's module GLBs and writes `assets/shelving/catalog.json` and
  `assets/shelving/modules/*.json`.
- **Do not edit the contract, the catalog or the bundles by hand.** To move a
  geometry change downstream, run `make site` in the pipeline: it copies the
  contract across, rebuilds these assets, bumps the version and runs the tests.
- `scripts/test-builder.mjs` fails if the catalog was built from a different
  contract than the one checked in, or if a pipeline checkout is present and its
  contract is newer. That check is the only thing standing between a Rhino edit
  and a deployed page whose geometry disagrees with its own catalog.

## Analytics and the event lake

`js/site.js` emits checkpoint events to `/api/track` (Netlify Blobs); the ops
runner in `../framework-ops` reads them back through `/api/export` and joins ad
→ site → WhatsApp. No PII ever goes into the lake — phone numbers live only in
Airtable. `docs/build-spec.md` and `docs/strategy.md` have the reasoning.

`/builder` deliberately does not load `js/site.js` (it would inject the site
header over a full-screen tool) and loads the pixel and gtag on
`requestIdleCallback`, after it is interactive.
